Wergonic · Client Panel

v1 Restructure Tasks

These tasks bring the real client-panel app in line with the agreed prototype. The prototype is the spec for flow, what data each section shows, and terminology. Tasks are sized to roughly half a day each. The deferred list at the end is intentionally out of scope.

34 tasks · 9 areas · prepared 18 June 2026

Navigation & structure 4 tasks

Reorganize the sidebar

Group the menu into Overview, Measurements, Risk, Workers, Setup and Administration, and show items by role. Ergonomists see everything except Team; admins see all. Leave out Actions and Risk overview for now.

Merge measurement views into one page

Replace the separate measurement menu items with a single Measurements page that has Active, Finished and Archived tabs, opening on Finished by default.

Rename Worker profiles to Workers and Users to Team

Update the menu labels, page titles and routes to match.

Move Work cycles into Work Library

Work cycles is no longer its own menu item. It becomes the first tab inside Work Library.

Home 3 tasks

Build a role-based Home

Show a different Home per role. Ergonomists get their personal worklist; admins get the oversight view, including license usage.

Add the Home inbox

Add one combined list of measurements that need attention and assessments to review, each with a quick action to open it.

Scope recent activity by role

Admins see the whole organization's recent activity; ergonomists see only their own.

Measurements list 4 tasks

Clean up the active measurements list

Remove the Recorded by column and remove the View logs action from active sessions.

Add a needs-attention filter

Add a filter on the Measurements page to show only measurements that failed or were interrupted.

Link methods to their assessments

Make the RAMP and MEC chips on a measurement open the Risk assessments list filtered to that measurement and method.

Add bulk actions on finished measurements

Let users select several finished measurements to compare, archive, delete or generate one combined report.

Measurement detail 6 tasks

Group the signal tabs

Replace the flat list of signals with grouped tabs: Movement, Physiological, Muscular rest, Distribution and Exposure limits.

Lead each signal with a summary

Each signal shows summary metric cards first and hides the full time series behind a "View full time series" expander.

Fix the measurement metrics wording

Show Median instead of Mean, rename Mean rest to Median rest, and drop the Peak metric.

Add the Exposure limits tab

Add a tab showing each body part's exposure against the recommended limits, with zone dots and percentiles.

Add P95 and P99 percentiles

Include the 95th and 99th percentiles in the distribution data and point heavy raw curves to the research export.

Add the risk summary band

Show the measurement's overall risk as a band at the top, based on the worst zone from its assessments.

Risk assessments 6 tasks

Show results as zones, not scores

Show RAMP and MEC results as green, yellow and red zones per factor. The overall level is the worst zone present, with the red, yellow and green counts shown.

Remove score and action-limit wording

Drop the 47/100 score and the "within/above action limit" wording. Use the zone label plus a measured-versus-guideline detail.

Make the assessment page status-aware

Reflect the assessment status (draft, needs review, complete) in the layout and remove the Duplicate action.

Move report generation off the assessment page

Remove the generate-report button and replace it with a quiet link to generate the report from the measurement.

Clean up the MEC assessment

Remove the Answers tab for MEC and add a comparison-to-action-limits table.

Define which methods auto-generate

Allow only RAMP and MEC to be generated from a measurement. RULA and REBA stay manual, created from the Risk assessments page.

Reports 3 tasks

Apply the new report model

A report only packages data that already exists and never runs an analysis. It is generated from the measurement, or from a standalone manual assessment.

One-click report with optional sections

Default to a single Wergonic risk assessment report template, with the section picker behind a Customize sections toggle.

Build the report sections

Build the report from Measurement info, Data analysis, Risk assessments, AI analysis and Appendix. The report is download-only.

Workers & privacy 3 tasks

Anonymize workers to Worker IDs

Identify measured workers only by an anonymized Worker ID such as W-001 everywhere. Staff keep their names and operators become Operator N.

Simplify the worker edit dialog

Use the Worker ID and remove the name and date-of-birth fields.

Add the worker detail page

Add a worker page listing that worker's measurement and assessment history.

Work Library 3 tasks

Build the Work Library

Create one Work Library with three tabs — Work cycles, Activities and Conditions. It is the shared vocabulary used to describe and group every measurement.

Define the Activities and Conditions vocabularies

Activities is a closed list of motions like Lifting and Fastening that recorders pick from. Conditions are whole-measurement circumstances like shift and environment, set as single or multiple choice. Line, station and factory come from Structure, not here.

Add vocabulary maintenance

Let admins rename, merge and retire vocabulary items, and flag rarely-used ones to keep the list clean.

Cross-cutting 2 tasks

Make AI a report section only

Remove standalone AI views. AI analysis appears only as a section inside the generated report.

Unify status colors

Use one status color system across the app and show the Generated status as amber "Needs review".

Deferred to v2 — no tasks now

  • Organisation risk index on Home, and the View risk overview entry point.
  • The entire Actions feature — the Home inbox keeps only needs-attention and to-review.
  • The entire Risk Overview page and its menu item.
  • Any worker-specific risk on the worker page — both current risk and risk trend over time.

REBA and RULA body drawings and RAMP's demonstrations stay. They are not removed; the restructure is about flow, data and terminology only.
