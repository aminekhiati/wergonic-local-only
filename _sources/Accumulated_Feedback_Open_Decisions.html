Decisions Needed
Before We Build

The feature description is complete on the method — how exposure is measured, projected and turned into a colour, and how the voice should behave. What it does not settle is a set of product choices that only you can make. They are listed here, once, so we are not stopping every second day to ask.

Each question says what it blocks and what we will assume if we do not hear otherwise. The eight marked Blocker genuinely stop work; the rest can be answered while we build the first parts.

18 August 2026 · against Accumulated Feedback — Feature Description, draft v1.3 (31 July 2026)
The short version

Four things decide the size of this feature.

  • How many body parts ship in v1. One (arm above shoulder) is a few weeks. Six is a different project — each one needs its own duration table and its own coaching phrases, written by an ergonomist, in two languages.
  • Whether we have tasks. Without tasks we can only forecast from the whole session, which is rough on a mixed workday. With tasks, someone has to start and stop them.
  • Whether we may call it RAMP. We measure arm angle; RAMP measures hand height. Until that is checked against real observation we can only honestly call it a RAMP-aligned estimate.
  • Whether a supervisor may see one named worker's numbers. That is a labour-relations decision, not a technical one, and it is far cheaper to make now than after it is built.

A · What ships in version 1

A1Which body parts and postures are in v1?Blocker

The description covers upper arm above shoulder, arm outside the work area, back bending, back twisting, neck forward and bent wrist. Every one of them needs its own duration bands, its own coaching sentences and its own testing.

If we hear nothing

We build upper arm above shoulder only, both arms, and design it so more can be added later without rework.

A2Who gives us the duration bands for each posture, and signs them off?Blocker

We have verified the table for arm above shoulder from the RAMP II guide. Every other posture needs the same, from someone who can be quoted. We are not comfortable inventing them.

A3Can we call the result "RAMP" at all?Blocker

RAMP scores hand height. Our sensors measure arm angle. They are close but not the same — bending the elbow changes hand height without changing arm angle. Nobody has checked how far apart they are in practice.

So: do we ship v1 labelled as an estimate aligned with RAMP, or hold the feature until someone films real work and compares? The second is more honest and much slower.

If we hear nothing

We ship it labelled as a RAMP-aligned estimate, and keep that wording away from anything that reads like a certified score.

A4One threshold set or two?

The description offers RAMP-based thresholds for assessment plus a second, looser set for technique training (the old 10 % / 30 % idea). Two sets means two configurations, two colours to explain, and a real risk of confusion.

If we hear nothing

v1 ships the RAMP-based set only.

B · Time, breaks and bad data

B1How does the app know a break has started?Blocker

Everything hangs off this — the percentages, the forecast, and the fact that the voice must not talk during lunch. Is it a button the worker presses, something the ergonomist marks, a fixed schedule, or do we guess it from the sensors going quiet?

B2How much missing data before we refuse to show a colour?

If a sensor drops for twenty minutes, the number we show is built on far less than it looks. We would rather grey it out and say "not enough data" than show a confident red. Where is that line — half the session, a quarter?

If we hear nothing

Below 70 % valid data we show the value greyed out and marked incomplete, and the voice stays quiet.

B3Must the end-of-session report agree exactly with what the worker saw live?

If yes — and it probably should be — the report has to count breaks and dropouts the same way this feature does, which means changing the report too. That is extra work worth knowing about now.

C · The forecast

The colour is a forecast: "if you keep working like this, you will end the shift at X". That needs to know how long the shift is and what work is still coming.

C1Do we have tasks in v1, and who starts them?Blocker

A worker doing overhead assembly for one hour and bench work for seven is not the same as one doing overhead work all day, but in the first twenty minutes the numbers look identical. Splitting the session into tasks is what makes the forecast defensible.

The question is who does the splitting: the worker taps start and stop on the phone, the ergonomist marks it, we detect it automatically, or we skip it in v1.

If we hear nothing

v1 forecasts from the whole session only, and tasks become the next step.

C2Where does shift length come from?

An 8-hour shift with 7 hours of actual work is the assumption. Fixed per company, per worker, or typed in when the session starts? Real shifts vary and the forecast scales directly with this number.

If we hear nothing

A company-level setting, 8 h / 7 h active, overridable when starting a session.

C3Does the colour follow the forecast or the minutes already worked?

We propose the forecast, because a warning that arrives after the damage is done is useless. The cost is that the colour can get better while the minutes only ever go up, and people will ask why. We show both numbers side by side to soften it, but you should agree with the trade before we build it.

D · The voice

D1What does the worker actually hear it on?Blocker

Phone speaker in a pocket, a headset, one earbud? A factory floor is loud, and the answer changes what we build and what we can promise. It also decides whether the worker can hear it at all with hearing protection on.

D2Which languages at launch, and who approves the wording?Blocker

Swedish and English is the assumption. These are not strings a developer can translate — the tone is the whole feature, and a clumsy sentence spoken every ten minutes will get the feature switched off.

D3Who writes the coaching sentences?Blocker

Lines like "try to raise your arm less" or "bring the work lower" have to come from an ergonomist — one per posture, plus a rest suggestion for each. We can draft them, but someone has to own and approve them.

D4Do you agree with the pacing?

First message after 10 minutes, then every 10 minutes, never more than 6 an hour, always one message about one body part — the worst one. Never two warnings at once, and praise when the worker fixes something.

If we hear nothing

We build exactly those numbers, all adjustable in settings.

D5Who can switch it on and off?

The worker, the ergonomist, or only a company admin? And is the whole feature off by default until someone turns it on?

If we hear nothing

Off by default; the ergonomist turns it on; the worker can mute the voice but not the measurement.

E · Screen and report

E1Who is the live screen for?

The worker glancing at their own phone, or the ergonomist standing beside them watching? They want very different amounts of detail — the worker wants a colour and a number, the ergonomist wants percentages and confidence.

If we hear nothing

One screen, worker-first, with the analyst detail behind a tap.

E2Does this appear in the end-of-session report, and how?

Minutes accumulated per posture, the final colour, and the messages spoken? And per arm, or only the worse arm — RAMP itself scores only the worse one, but an ergonomist usually wants to see both.

E3Anything in the web panel in v1, or mobile only?

A live view for an ergonomist watching from a desk, historical trends, threshold configuration — each is separate work on the web side. Mobile-only is the smaller v1.

If we hear nothing

Mobile only, plus whatever lands in the existing report.

F · People and data

F1Can a supervisor see one named worker's exposure?Blocker

This feature produces, for the first time, a continuous per-person record of how someone worked all day, plus a log of every time they were corrected. In Sweden and most of Europe that is a works-council conversation, not a settings toggle.

We need to know now whether that data is visible per person, only to the ergonomist, or only as a group average — it changes the database, the permissions and the report.

F2Do we keep a log of every message spoken?

Cheap to store now, and it is the only way to later answer "does saying this actually change anything". But it is also a record of a named person being corrected, so it is your call, not ours.

If we hear nothing

We log messages against the session, visible to the ergonomist only.

G · Confirming what is out

G1Customer-written coaching messages — out of v1?

Letting each customer's own ergonomist write their own sentences ("use the lift table" instead of "bring the work lower") is described as a future feature. We assume it is out of v1 entirely, including the small first version where a company can override just the technique phrases. Confirm, because it is the difference between shipping one message set and shipping an editor.

G2Vibration stays instant-only?

The buzz keeps meaning "your posture is bad right now" and never means "you have accumulated too much". Accumulated feedback speaks and shows, but never buzzes — otherwise the worker cannot tell the two apart.
